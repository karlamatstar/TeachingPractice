# 프리랜서 마케터 포트폴리오 웹페이지 PRD

## 1. 제품 개요

목표는 하나입니다. 채용 담당자가 페이지를 열고 30초 안에 "이 사람, 쓸 수 있겠다"는 판단을 내리게 만드는 것.
정보를 많이 넣는 게 아니라, 핵심 신호를 빠르게 전달하는 설계가 중심이어야 합니다.

사용자는 두 명입니다. 페이지를 보여줄 채용 담당자(읽는 사람)와, 포트폴리오를 만들 마케터 본인(쓰는 사람).
PRD는 이 두 관점을 모두 충족해야 합니다.

---

## 2. 핵심 요구사항 (Must-have)

### 30초 스캔 설계 원칙

채용 담당자의 시선 흐름은 예측 가능합니다. F-패턴 또는 Z-패턴으로 움직이고, 숫자와 굵은 글씨에 먼저 멈춥니다.
이 원칙을 페이지 전체에 적용해야 합니다.

구체적으로 필요한 것들:

- 첫 화면(Above the fold)에 이름, 직함, 핵심 수치 3개, 연락 버튼이 모두 들어와야 합니다.
- 스크롤 없이 누구인지, 무엇을 했는지, 어떻게 연락하는지가 다 보여야 합니다.
- 핵심 수치는 "마케팅 ROI 340% 달성", "캠페인 집행 예산 누적 12억", "클라이언트 유지율 91%" 같은 형태로, 임팩트를 숫자로 증명해야 합니다.
- 본인의 실제 데이터로 채워야 효과가 있습니다.
- 프로젝트 카드는 최대 4개.
- 각 카드에 클라이언트명(또는 익명 처리), 담당 업무, 결과 수치, 사용 채널/툴만 표시합니다.
- 텍스트 단락은 지양하고, 스캔 가능한 구조여야 합니다.

## 3. 섹션 구성 및 우선순위

| 섹션 | 위치 | 목적 |
|---|---|---|
| Hero | 최상단 | 정체성 + 수치 + CTA |
| 핵심 역량 | 2번째 | 무엇을 잘 하는가 (3개) |
| 프로젝트 | 3번째 | 무엇을 해봤는가 (4개) |
| 클라이언트 로고 | 4번째 | 신뢰 증거 |
| 추천사 | 5번째 | 사회적 증거 |
| Contact | 최하단 | 연락처 + 링크 |

섹션이 많으면 오히려 희석됩니다. 이 6개가 최대입니다.

## 4. 기술 방향

### 스택 선택 기준

빠르게 배포 가능하고, 유지보수가 쉽고, 성능이 좋을 것.

추천 스택은 순수 HTML/CSS/JS 단일 파일 또는 Next.js 정적 사이트(SSG) 두 가지입니다.

프리랜서 포트폴리오라면 단일 HTML 파일이 현실적으로 가장 좋습니다.
GitHub Pages나 Netlify에 파일 하나 올리면 끝이고, 도메인 연결도 15분이면 됩니다.
프레임워크 빌드 환경 없이 즉시 수정 가능합니다.

Next.js는 나중에 블로그나 케이스 스터디 페이지를 추가할 계획을 선택합니다.

### 성능 요건

- Lighthouse 점수 90 이상.
- 채용 담당자가 모바일로 열었을 때 3초 안에 로딩돼야 합니다.
- 이미지는 WebP, 폰트는 Google Fonts 또는 system-font 사용.

### 배포

- Netlify 무료 플랜 권장.
- 커스텀 도메인 연결, HTTPS 자동 설정, 폼 제출 기능(Contact 섹션용)을 모두 무료로 제공합니다.

## 5. 디자인 방향

- 마케터 포트폴리오의 디자인은 "나는 디자인도 할 줄 안다"가 아니라 "나는 메시지를 구조화할 줄 안다"를 보여줘야 합니다.
- 과하게 화려하면 오히려 마이너스입니다.

### 추천 방향

- 여백이 넓은 미니멀
- 타이포그래피 중심
- 강조 색상 1개(브랜드 컬러)
- 다크/라이트 모드 지원은 필수는 아니지만 있으면 좋습니다.

### 금지 사항

- 애니메이션 과다
- 스크롤 패럴랙스
- 자동 재생 영상
- 팝업

---

## 6. Non-functional 요구사항

- 모바일 반응형은 필수입니다.
- 채용 담당자의 약 40%는 모바일로 첫 확인을 합니다.
- 히어로 섹션과 수치 카드가 모바일에서도 깔끔하게 보여야 합니다.
- SEO는 기본만: 제목 태그, 메타 디스크립션, OG 태그(링크 공유 시 미리보기).
- 이름 + "마케터" 검색에서 상위 노출을 목표로 합니다.
- Contact 폼은 Netlify Forms 또는 Formspree로 구현합니다.
- 백엔드 없이 이메일 수신이 가능합니다.
