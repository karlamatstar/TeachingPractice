# [PRD] 프리랜서 마케터 포트폴리오 웹사이트 요구사항 정의서

## 1. 프로젝트 개요

| 구분 | 상세 내용 |
| --- | --- |
| 프로젝트명 | 프리랜서 마케터 전환을 위한 개인 포트폴리오 웹사이트 구축 |
| 핵심 목표 | 채용 담당자 및 클라이언트가 접속 후 '30초 이내'에 마케터의 핵심 역량과 성과를 파악할 수 있도록 직관적이고 임팩트 있는 경험 제공 |
| 타겟 유저 | 기업의 채용 담당자, 마케팅 에이전시 소싱 담당자, 외부 프로젝트 의뢰인 |
| 핵심 지표 | 사이트 체류 시간 증가, 포트폴리오(PDF) 다운로드 수, 컨택 폼(Contact Form) 제출 횟수 |

## 2. 사이트 맵 (메뉴 구조)

단일 페이지(One-page)의 스크롤 압박을 피하고, 정보를 구조화하기 위해 총 4개의 다중 페이지 레이아웃으로 구성합니다.

- Home (메인 화면): 강력한 후킹 텍스트와 핵심 성과 요약
- About Me (소개): 마케터로서의 철학, 스택, 업무 연혁
- Projects (포트폴리오): 주요 마케팅 캠페인 상세 케이스 스터디
- Contact (문의): 의뢰 폼 및 이력서 다운로드

## 3. 페이지별 세부 화면 및 기능 요구사항

### 3-1. Home (메인 페이지)

채용 담당자의 첫인상을 결정하는 가장 중요한 랜딩 페이지입니다.

| 레이아웃 구분 | 기능 및 콘텐츠 상세 요구사항 | 테스트/QA 확인 포인트 |
| --- | --- | --- |
| 글로벌 헤더 (GNB) | 사이트 로고, 4개 메뉴(Home, About, Projects, Contact) 노출. 스크롤 시 상단에 고정(Sticky)되어야 함. | 스크롤을 내려도 GNB가 상단에 정상 고정되는지 확인 |
| 히어로 섹션 (상단) | "데이터로 증명하는 마케터, OOO입니다" 등의 임팩트 있는 카피라이팅 노출. 배경은 동적 애니메이션 적용. | 해상도 변경 시 텍스트가 잘리거나 애니메이션 지연이 없는지 확인 |
| 30초 성과 요약 (중단) | 'ROAS 300% 달성', '전환율 50% 개선' 등 핵심 성과 3가지를 움직이는 숫자 카운팅 애니메이션으로 구현. | 로딩 시 숫자가 0에서 목표치까지 정상적으로 카운팅되는지 확인 |
| CTA (Call To Action) | '전체 프로젝트 보기', '이력서 다운로드' 버튼 2개를 중앙에 배치. 마우스 오버(Hover) 시 버튼 색상 반전. | 버튼 클릭 시 해당 페이지 및 다운로드 링크로 즉시 연결되는지 확인 |

### 3-2. About Me (소개 페이지)

마케터의 기술적 역량과 업무 스토리를 증명하는 페이지입니다.

| 레이아웃 구분 | 기능 및 콘텐츠 상세 요구사항 | 테스트/QA 확인 포인트 |
| --- | --- | --- |
| 핵심 스킬 스택 | 퍼포먼스 마케팅, SEO, 콘텐츠 기획 등 보유 기술을 막대그래프 또는 레이더 차트 UI로 시각화하여 제공. | 차트 플러그인이 모바일 환경에서도 정상적인 비율로 렌더링되는지 확인 |
| 타임라인 연혁 | 연도별 주요 프로젝트 이력과 프리랜서 전환 과정을 세로형 타임라인(Timeline) UI로 구성하여 스크롤 시 순차적으로 나타나도록(Fade-in) 처리. | 스크롤 이벤트에 맞춰 타임라인 애니메이션이 끊김 없이 부드럽게 작동하는지 확인 |

### 3-3. Projects (프로젝트 상세 페이지)

가장 방대한 데이터가 들어가는 곳으로, 갤러리 형태의 레이아웃이 필요합니다.

| 레이아웃 구분 | 기능 및 콘텐츠 상세 요구사항 | 테스트/QA 확인 포인트 |
| --- | --- | --- |
| 카테고리 필터링 | 상단에 '전체', '퍼포먼스', '콘텐츠', 'CRM' 탭을 제공. 탭 클릭 시 화면 전환 없이 아래의 썸네일들이 비동기(AJAX)로 즉시 필터링. | 필터 클릭 시 해당하는 항목의 썸네일만 정확하게 정렬되어 노출되는지 확인 |
| 갤러리 그리드 | 썸네일 이미지, 캠페인명, 기간, 핵심 성과를 카드(Card) 형태로 나열. 한 줄에 PC는 3개, 태블릿은 2개, 모바일은 1개씩 정렬(반응형). | 각 기기별 해상도에서 카드의 개수와 여백(Margin)이 깨지지 않는지 뷰포트 테스트 |
| 프로젝트 상세 모달 | 카드 클릭 시 새 페이지로 가지 않고, 팝업(Modal) 형태로 '문제 인식 - 해결 과정 - 결과(ROI)'가 상세히 노출. 닫기(X) 버튼 필수. | 모달 창이 떴을 때 배경 스크롤이 차단되는지, 닫기 버튼이 정상 작동하는지 확인 |

### 3-4. Contact (연락처 및 의뢰 페이지)

최종적인 액션(의뢰, 연락)을 유도하고 데이터를 수집하는 페이지입니다.

| 레이아웃 구분 | 기능 및 콘텐츠 상세 요구사항 | 테스트/QA 확인 포인트 |
| --- | --- | --- |
| 이메일 발송 폼 | 발신자명, 이메일 주소, 제목, 문의 내용(Textarea)을 입력받는 폼 제공. '전송' 클릭 시 백엔드 API를 통해 마케터의 이메일로 자동 전달. | 필수 입력값 누락 시 에러 메시지(Validation) 출력 확인, 전송 후 '성공 메시지' 노출 확인 |
| 링크 및 다운로드 | LinkedIn 외부 링크 아이콘 버튼 배치. 포트폴리오(PDF)를 다운로드할 수 있는 영역 분리 제공. | 외부 링크 클릭 시 새 창(target="_blank")으로 열리는지, PDF 파일이 손상 없이 다운로드되는지 확인 |

## 4. 비기능적 요구사항 (기술 및 인프라)

시스템의 성능과 안정성을 규정하는 항목입니다.

- '반응형 웹 지원': 모바일, 태블릿, 데스크톱 환경에 맞춰 UI가 유동적으로 변환되어야 합니다.
- '성능 최적화 (로딩 속도)': 채용 담당자의 이탈을 막기 위해, 고해상도 이미지는 WebP 포맷으로 압축하여 초기 로딩 속도를 3초 이내로 맞춥니다.
- '크로스 브라우징': Chrome, Safari, Edge 브라우저에서 동일한 화면과 기능을 보장해야 합니다.
- '보안': Contact 폼에서 악의적인 스크립트가 실행되지 않도록 입력값 필터링(XSS 방어) 처리를 적용해야 합니다.
