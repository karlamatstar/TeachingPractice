# 챗봇 답변 품질 결함 보고서 운영 계획

## 1. 개요
단순 서버 인프라 장애(500 에러, 지연 등)가 아닌, **AI 챗봇의 실제 답변 품질 이상(환각 현상, 부정확한 정보 제공, 맥락 이탈 등)** 에 초점을 맞춘 전용 결함 보고서 작성 프로세스입니다.

## 2. 운영 워크플로우 (Workflow)
1. **품질 이상 탐지**: 채점 모델(`gpt-4o`)이 챗봇의 답변을 실시간/배치로 평가하여 `FAIL` 또는 `REVIEW` 판정.
2. **Jira 자동 등록**: 해당 질문과 답변 내역이 Jira `BUG-1 (결함 자동 모음)` 에픽 하위에 버그 티켓으로 자동 생성.
3. **결함 보고서 일일 생성 및 누적 (Append)**: 실시간 채팅 1건마다 파일을 새로 만들지 않습니다. 시스템이 날짜를 체크하여, **매일 그 날짜의 첫 결함이 발생할 때 새로운 마크다운 파일**(예: `_OUTPUT/quality/defects/chatbot/chatbot_defect_report_20260708.md`)을 1개만 자동 생성합니다. 이후 하루 동안 발생하는 모든 결함은 해당 파일 맨 아래에 계속 **이어 붙여서(Append)** 기록됩니다. (날짜가 바뀌면 자동으로 새 파일이 만들어짐)
4. **수동 스크립트 및 배치 파일(.bat)을 통한 최종 Word 변환**: 매 채팅마다 워드를 자동 생성하면 비효율적이므로, 보고서가 쌓이는 해당 폴더 내에 전용 변환 파이썬 스크립트(`generate_word_report.py`)와 함께 **실행용 배치 파일(`generate_report.bat`)**을 만들어 둡니다. 터미널 조작이 낯선 QA 담당자라도 퇴근 전 `.bat` 파일만 더블 클릭하면, 그날 누적된 MD 파일을 긁어와 'QA 검토 의견'이 추가된 최종 Word(`.docx`) 보고서를 단 한 번에 찍어냅니다.

## 3. 챗봇 품질 결함 보고서 작성 기준 (양식)
장애 모의훈련 보고서와는 다르게 **"프롬프트, RAG 데이터, 점수"** 위주로 구성됩니다.

| 항목 | 시스템 자동 작성 내용 |
|---|---|
| **발생 일시 및 ID** | 2026-07-08 14:20:00 / Req ID: req-12345 |
| **결함 제목** | *(무슨 결함이 발생했는가?)* [품질 이상] 요금제 안내 시 잘못된 금액 제공 (환각 발생) |
| **재현 절차** | *(어떻게 재현했는가?)* 사용자 원본 질문 입력: "프리미엄 요금제는 한 달에 얼마인가요?" |
| **기대 결과** | *(기대 결과는 무엇이었는가?)* 정답 기준에 맞는 정확한 금액(20,000원) 안내 및 정책 준수 |
| **실제 결과** | *(실제 결과는 무엇이었는가?)* 챗봇 실제 답변: "월 15,000원입니다." / 모델 평가: FAIL (정확성 0점) |
| **영향도** | *(사용자에게 어떤 영향이 있는가?)* 잘못된 가격 안내로 인한 고객 클레임 및 금전적 손실 유발 위험 (High) |
| **원인 추정** | *(원인은 무엇으로 추정되는가?)* RAG(검색 증강 생성) 과정에서 과거(2024년) 구버전 요금제 문서를 참조한 것으로 판단됨 |
| **조치 방안** | *(어떻게 조치해야 하는가?)* 벡터 DB에서 구버전 문서 삭제 및 최신 요금표 재색인, 프롬프트 페널티 강화 |
| **재시험 및 QA 검토** | *(조치 후 다시 테스트했는가?)* 조치 후 재검증(Regression Test) 수행 예정. 💡 *QA 엔지니어 코멘트: "치명적인 오류이므로 유사 질문 50건 추가 검증 필요"* |

## 4. 최종 Word 보고서 양식 (Template)
자동화 스크립트(`.bat`)를 통해 생성되는 워드 문서는 단순한 텍스트 복붙이 아닌, 실제 결재를 올릴 수 있는 기안(숙제 제출용) 느낌의 포멀한 양식을 가집니다.

* **문서 제목 (Title)**: 챗봇 답변 품질 일일 결함 보고서 (생성일자)
* **결함 요약 (Summary)**: 금일 발생한 총 결함 건수(FAIL/REVIEW) 및 주요 원인 요약.
* **결함 상세 표 (Table)**: 위의 3번 항목(MD 표)의 내용이 깔끔한 워드 표(Table) 디자인으로 삽입됨.
* **💡 QA 엔지니어 검토 의견 (Highlight)**: 각 결함 표 바로 아래에, 담당자(QA 엔지니어)가 직접 꼼꼼하게 분석하고 코멘트한 것처럼 작성된 '원인 분석 및 조치 의견' 단락이 강조된 폰트(예: 이탤릭체 또는 파란색 글씨)로 추가됨. (제출자가 한 번 더 손보고 정리한 느낌을 완벽하게 주기 위함)

## 5. 인프라 장애 보고서(Chaos Test)와의 차이점
* **인프라 장애 보고서 (BUG-4)**: 서버 다운, 타임아웃 등 **시스템 엔지니어링** 관점의 인프라 이슈 (HTTP 상태코드, 지연 속도, 트래픽 등).
* **챗봇 품질 결함 보고서 (BUG-1)**: 답변의 정확성, 정책 위반 등 **AI 로직 및 데이터 품질** 관점의 이슈 (환각, RAG 검색 실패, 프롬프트 한계 등).
