# 챗봇 지식베이스(Knowledge Base) 고도화 기획서

## 1. 고도화 방향 (결정 사항)
현재 `app/knowledge_base.py` 파일의 파이썬 딕셔너리(`COURSE_KNOWLEDGE`) 형태를 외부 파일이나 DB로 분리하지 않고 **그대로 유지**하되, **내부 리스트(데이터 항목)를 대폭 확장**하는 "내실 다지기" 방향으로 고도화를 진행합니다.
- 복잡한 외부 DB 연동(RAG) 전환을 피하여, "0원의 유지 비용"과 "지연 없는 즉각적인 응답 속도"라는 규칙 기반(Rule-based) 구조의 장점을 극대화합니다.
- 불필요한 오버엔지니어링을 지양하고 현재 아키텍처의 강점에 집중하는 전략입니다.

---

## 2. 상세 작업 계획

### 2.1. `app/knowledge_base.py` 데이터 확장
기존의 단순한 5~6개 항목에서 벗어나, 실제 교육 과정 안내 챗봇에 필요한 실무적인 엣지 케이스(Edge Case)들을 딕셔너리에 대거 추가합니다.

**[추가 예정 항목 예시]**
- `curriculum_details`: 커리큘럼 세부 과목 및 학습 목표 안내
- `evaluation_criteria`: 단위 평가, 시험 커트라인 및 재시험 기준
- `equipment_support`: 훈련 장비(노트북 렌탈), 교재 및 중식비 지원 여부
- `holiday_rule`: 공휴일 및 주말 보충 수업 진행 여부
- `drop_out_policy`: 중도 포기(하차) 시 패널티 및 지원금 환수 규정

### 2.2. 연계 모듈 (`app/rule_based_agent.py`) 리팩토링
확장된 딕셔너리 데이터에 정확히 대응하도록, 키워드 매칭 로직을 정교하게 다듬습니다.

- **부분적 방어 및 의도적인 한계 유지 (대조군 역할 보존)**:
  - **띄어쓰기 예외 처리 (최소 방어)**: 검색 전 사용자 질문의 공백을 모두 제거(`question.replace(" ", "")`)하는 간단한 로직만 추가하여, "교 육 시 간"과 "교육시간" 정도의 단순 띄어쓰기 차이는 정상 인지하도록 만듭니다. (최소한의 기본 챗봇 구실)
  - **오타 방어 배제 (한계 유지)**: 반면 사용자가 명백한 오타를 냈을 때(예: "출선률")는 챗봇이 인지하지 못하고 오답을 내도록 **의도적으로 방치**합니다.
  - **설계 목적**: 오타로 인해 멍청한 오답이 나와야만 AI 채점 시스템에서 `FAIL`이나 `REVIEW` 판정이 발생하고, 이를 통해 우리가 기획한 **[Jira 자동 버그 등록(BUG-1)]** 파이프라인이 자연스럽게 시연될 수 있습니다.
- **분기문(조건) 확장**: 추가된 지식을 답변할 수 있도록 `if "커리큘럼" in question` 수준의 정직하고 단순한 1차원적 매칭 로직만 추가하여, 구어체나 복잡한 질문에는 자연스럽게 실패하도록 유도합니다.
- **코드 구조 개선 (옵션)**: `if-elif` 문이 너무 길어져 가독성이 떨어지는 것을 방지하기 위해, "딕셔너리의 Key"와 "매칭할 키워드 리스트"를 묶어두는 매핑 구조로 리팩토링하여 유지보수성을 높입니다.

## 3. 향후 작업 순서 (Action Items)
1. `knowledge_base.py` 딕셔너리에 새롭게 추가할 시나리오 텍스트(Mock Data) 작성.
2. `rule_based_agent.py` 파일의 로직을 수정하여 확장된 데이터와 키워드 연결.
3. 로컬 서버 실행 후 챗봇 UI를 통해 새로 추가된 키워드들을 질문해 보며 응답(규칙 기반 대조군) 정상 작동 여부 검증.
