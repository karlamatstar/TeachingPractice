# AI 에이전트 품질 검증 포트폴리오 작업 진행 로드맵 (Master Roadmap)

이 문서는 `_DOCS/future_plans/` 폴더 내의 7개 기획 문서들을 실제 코드로 구현하기 위한 전체 작업 진행 순서도(Phase)입니다. 의존성이 낮고 가장 코어가 되는 시스템부터 구축하여 점진적으로 파이프라인을 조립해 나갑니다.

## [Phase 1] 기초 공사 (보고서 및 Jira 시스템 연동)
가장 독립적이고, 이후 다른 모든 테스트 파이프라인이 종료된 후 공통으로 호출하게 될 핵심 '결함 리포팅 모듈'부터 구현합니다.

- **관련 문서**: 
  - `chatbot_defect_report_plan.md`
  - `jira_integration_plan.md`
- **구현 목표**:
  1. 마크다운(.md) 형태의 테스트 결과를 QA 표준 8대 질문 양식에 맞게 포맷팅하는 파이썬 모듈 작성.
  2. 작성된 마크다운을 최종 제출용 Word(`.docx`) 파일로 자동 변환하는 로직(`python-docx`) 구현.
  3. 발견된 결함(에러 로그, 상태 코드 등)을 Jira API를 통해 프로젝트 보드(BUG-4 에픽 등)에 자동 등록하는 연동 모듈 작성.

## [Phase 2] 통합 QA 자동화 (검증 테스트 탭)
Phase 1에서 만든 보고서 및 지라 연동 모듈을 활용하여, 장애 훈련과 기능 검증(Pytest)을 하나의 파이프라인으로 묶습니다.

- **관련 문서**: 
  - `k6_chaos_test_plan.md`
  - `pytest_automation_plan.md`
- **구현 목표**:
  1. `/fault-lab`을 호출해 고의로 인프라 장애(500 에러, 지연 등)를 유발하는 K6 테스트 스크립트 작성 (FL-001 ~ 006).
  2. 장애 발생 환경에서도 챗봇 방어력을 검증하는 Pytest 스크립트 실행 로직 연동 (FL-007).
  3. GUI 런처(`test_launcher.py`)에 **'검증 테스트'** 탭을 신설.
  4. 버튼 클릭 시 `장애 훈련 ➔ 파이테스트 ➔ 결함 보고서(MD/Word) 생성`이 릴레이로 실행되는 로직 연결 및 터미널 뷰어 연동. (단, 의도적인 장애 테스트이므로 Jira 자동 등록은 비활성화)
  5. GUI에서 결과 확인 시 Word(.docx) 대신 웹에서 마크다운(.md) 리포트를 직접 조회하도록 연동.

## [Phase 3] K6 종합 성능 및 신뢰성 분석 (성능 테스트 탭)
기존 DB나 리포팅 시스템을 거치지 않는(Bypass) 완전히 독립적인 고도화된 계단식 부하 테스트를 구축합니다.

- **관련 문서**: 
  - `k6_api_latency_test_plan.md`
- **구현 목표**:
  1. 선별된 10개의 테스트 케이스를 바탕으로 계단식 부하(1명 ➔ 5명 ➔ 10명)를 가하는 K6 스크립트 작성.
  2. K6의 사용자 정의 지표(Custom Metrics)와 검증(Checks)을 활용해 6대 핵심 질문의 해답을 구하는 로직 적용.
  3. 테스트 종료 즉시 `performance_report.html(또는 .md)`을 생성.
  4. GUI 런처에 **'API 종합 성능 테스트'** 탭 신설, 과금 경고 팝업 로직 적용 및 `[성능 보고서 확인]` 원격 열람(Static 서빙) 기능 구현.

## [Phase 4] 챗봇 지능 및 지식 고도화 (Final)
탄탄하게 구축된 검증 파이프라인을 바탕으로, 실제 AI 모델의 성능과 RAG 지식베이스를 업그레이드합니다.

- **관련 문서**:
  - `knowledge_base_upgrade_plan.md`
  - `model_upgrade_plan.md`
- **구현 목표**:
  1. 벡터 DB(ChromaDB 등)의 문서 청킹(Chunking) 방식 및 검색 품질 개선.
  2. LLM 모델(예: 시스템 프롬프트 최적화, temperature 조절 등) 업그레이드.
  3. 업그레이드 후 앞서 구축한 [Phase 2]와 [Phase 3]의 파이프라인을 돌려 품질 향상 여부를 객관적인 수치로 증명.
