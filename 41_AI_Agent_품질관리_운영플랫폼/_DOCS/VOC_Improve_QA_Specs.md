# VOC Improve 및 QA 프로젝트 기획안

## 1. 프로젝트 개요 및 구조
* **목적**: 6개의 협업 AI 에이전트(`interpreter`, `retriever`, `summarizer`, `evaluator`, `critic`, `improver`)와 gRPC, MCP 프로토콜을 사용하여 고객의 불만사항(VOC)을 분석하고, 최종적으로 정책 개선안을 도출하는 시스템입니다.
* **구조**: `main.py`가 MCP 서버의 메인 진입점 역할을 하고, `grpc_server.py`가 전체 6개 에이전트를 오케스트레이션(조율)합니다.

## 2. QA 과제 1 - 내부 품질 진단
* **목표**: 에이전트 서버의 정상 실행 여부, gRPC 연결, 데이터 품질(사실 왜곡 방지), AI 답변 품질 및 장애 대응 등을 종합적으로 점검합니다.
* **제안된 폴더 구조 및 구성 요소**: 
  `quality_diagnosis/` 폴더 내에 다음 파일들로 구성할 것을 제안합니다.
  * `test_cases.json`: 20개의 테스트 질문 모음
  * `test_pipeline_e2e.py`: End-to-End 파이프라인 테스트 스크립트
  * `test_fault_tolerance.py`: 장애 대응 테스트 스크립트
  * 루브릭 기준(채점 기준)
* **품질 판정 기준 (100점 만점)**: 
  * **90점 이상**: 배포 진행
  * **69점 이하**: 배포 보류
  * **치명적인 문제**(개인정보 노출, 허위 사실 등) 발생 시: 점수와 관계없이 즉각 배포 보류

## 3. QA 과제 2 - 독립적인 LLM Judge
* **목표**: 답변 생성에 관여하지 않은 외부 LLM 모델을 활용해 최종 답변 품질을 객관적으로 채점 및 평가합니다. (예: 답변 생성은 OpenAI 사용, 품질 평가는 Anthropic 사용 등 생성 모델과 평가 모델 분리)
* **평가 기준 (5가지 루브릭)**:
  1. **정확성**
  2. **요약 충실성**
  3. **정책 구체성**
  4. **유용성**
  5. **안전성**
